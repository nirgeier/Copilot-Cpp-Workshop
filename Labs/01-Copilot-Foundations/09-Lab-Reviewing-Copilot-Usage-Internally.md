# 9. Reviewing Copilot Usage Internally

!!! abstract "About this Lab"
    - Administrators see adoption, engagement, credit consumption, and configuration changes in different views.
    - Each view has coverage limits that shape an enablement decision.



!!! note "Latest changes"
    The November 2026 releases added new models, connectors, review controls, and monitoring. See [20. Latest Copilot Changes](20-Latest-Copilot-Changes.md) for the current status.

## 1. Four Different Views

- Do not mix these up.
- They answer different questions.

| View | Question it answers | Owner |
|------|---------------------|-------|
| Individual AI usage page | What did I consume and on which models | Each developer |
| Organization activity report | Who last used Copilot and how seats are assigned | Org owner |
| Copilot usage metrics dashboards | How teams adopt Copilot and how it relates to PR flow | Admin or decision maker |
| Audit log | Who changed a policy or content exclusion | Admin |

## 2. Individual Usage

- Business and Enterprise users: profile picture, Copilot settings, then **Usage this cycle**.
- Individual users: billing settings, then **AI usage**, which shows included credits, additional usage, a model chart, and a per model breakdown.
- IDEs show plan allowance and reset dates in the Copilot status control. Visual Studio labels this **Copilot Consumptions**, JetBrains uses **View quota usage**.

!!! note "What the billing view cannot tell you"
    - The AI usage page shows credits and cost by model.
    - It generally does not trace a credit to a specific prompt, session, or feature at request level.
    - Do not present it as a per task cost report.

## 3. Organization Activity

- In the organization settings, the Copilot overview shows assigned seats and estimated monthly cost.
- Access management can sort users by last activity.
- The **Activity report** downloads as CSV.
- The REST API returns seat information and per user assignment details.
- `last_activity_at` can lag. Wait 24 hours and check telemetry settings in the IDE before escalating.

## 4. Usage Metrics Dashboards

GitHub documents four dashboards:

| Dashboard | What it shows |
|-----------|---------------|
| Usage metrics | Adoption and engagement trends |
| Code generation | Code generated by users and agents |
| Impact | Adoption depth against pull request output and time to merge |
| Repository insights | PR activity and code review outcomes for one organization owned repo |

- Metrics categories include adoption, engagement, acceptance rate, lines of code, and pull request lifecycle.
- Adoption cohorts group users by the features they use, from completions to agent and multi agent workflows.

!!! warning "Association is not causation"
    - Dashboard comparisons show associations, not proof that Copilot caused a change in delivery.
    - Team composition, project complexity, and experience also affect the numbers.
    - Combine trends with developer feedback.

Coverage limits matter:

- Detailed IDE breakdowns need supported clients with telemetry enabled.
- Server side telemetry can still identify active users when client detail is missing.
- Repository insights uses server side PR and review data.
- Data for a day is available within two full UTC days after that day closes.
- Organization totals can overlap because one user can belong to several organizations. Do not add them into an enterprise total.
- Usage metrics measure activity, not license assignments. Use the user management API for seats.

For custom reporting or long term storage, use the usage metrics APIs or NDJSON exports.

## 5. Request Level Debug Views

Billing and dashboard views report aggregates. They do not trace a credit to one prompt or session. To inspect what actually reached a model, use a local debug view.

| Surface | View or command | What it shows |
|---------|-----------------|---------------|
| VS Code Chat | Chat Debug view | System prompt, user prompt, resolved context, response, tool responses |
| VS Code Agents | Agent Debug Logs panel, Summary view | Tool calls, token usage, errors, duration |
| VS Code Agents | Logs view | Chronological events, expandable to prompts and tool input and output |
| Copilot CLI | `/context` | Context window token usage |
| Copilot CLI | `/usage` | Per-model token totals and credits where billed |
| Copilot CLI | `--log-level debug` plus `/session` | Verbose events and the session log path |

- The Agent Debug Logs panel is in preview. Enable `chat.agentHost.agentDebugLog.enabled` before you reproduce an issue; capture is not retroactive.
- Open Chat Debug view from the Chat view overflow menu or with **Developer: Show Chat Debug View**. Use **Developer: Open Agent Debug Logs** for the panel.
- Check that custom instructions, the attached header, and the validation commands appear in the request. If they do not, the problem is context, not the model.

- [ ] Enable the preview setting in VS Code, ask a grounded question about `preprocess`, and open the Chat Debug view.
- [ ] Record which repository instructions and files reached the model.
- [ ] Run `/context` and `/usage` in Copilot CLI and compare the two views.
- [ ] Export a session log only if policy allows, and review it for secrets before sharing.

!!! warning "Debug output is sensitive"
    - Debug views and logs can contain prompts, source code, file paths, and tool output.
    - Keep them local. Do not commit them or paste them into a public issue.

## Reference

### Usage view and field reference

| View or field | Source | Meaning |
|---------------|--------|---------|
| AI usage page | Individual billing settings | Credits and cost by model, not per prompt |
| Activity report | Organization settings, CSV download | Seats and last activity |
| `last_activity_at` | REST API and metrics data | Can lag; wait 24 hours before escalating |
| Adoption cohorts | Usage metrics dashboards | Groups users by the features they use |
| `excluded_paths` | Audit log after `copilot.content_exclusion_changed` | Paths excluded after the change |
| Chat Debug view | VS Code Chat overflow menu | Prompt, context, and tool definitions sent to the model |
| Agent Debug Logs | VS Code Agents panel, in preview | Token usage, errors, duration, chronological events |
| `/context` and `/usage` | Copilot CLI | Context window use and per-model token totals |

- Data for a day is available within two full UTC days after that day closes.
- Organization totals can overlap because one user can belong to several organizations.
- Usage metrics measure activity, not license assignments. Use the user management API for seats.

!!! note "Interpretation limits"
    - Dashboard comparisons show association, not causation.
    - Repository insights needs an organization owned repository and server side PR data.
    - Never copy personal usage data into the repository.

## Example

A completed one page brief from the available views:

```markdown
# Copilot enablement brief

## Adoption
- Seats assigned: 12. Active users this month: 9.
- Trend: steady for three weeks.

## Depth
- Completions dominate. Agent mode use is limited to two developers.
- Adoption cohort: code-first, with early agent exploration.

## Cost
- AI credits by model: fast model 70 percent, reasoning model 30 percent.
- No budget alert in this cycle.

## Next step
- Run a context engineering and mode selection clinic, then review the
  adoption cohorts again after two weeks.

## Limits
- Dashboard comparisons are associations, not proof of causation.
- This view shows credits by model, not credits per prompt.
```
